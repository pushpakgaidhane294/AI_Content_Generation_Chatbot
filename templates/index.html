Academic Project Overview & Viva Documentation

Generative AI Project: Architecture, Theory, and Prompt Engineering System.

Project Overview & Objective

Title: AI Content Generation Chatbot Using LLM and Prompt Engineering

Objective: To build a production-style generative AI tool capable of dynamically engineering prompts for distinct content formats (Emails, Reports, Technical Explanations, General Content) while managing tone, audience depth, and length constraints on a local, private LLM runtime.

Key Philosophy: Never send raw, unconstrained user input directly to an LLM. Always orchestrate through a dedicated prompt engineering layer.

Technology Stack

  • Frontend: HTML5, CSS3, Vanilla JavaScript (No React, No Streamlit)
  • Backend: Python, FastAPI, Uvicorn, Pydantic v2
  • AI Runtime: Ollama with llama3.2 (3.2B parameters)
  • Database: SQLite with SQLAlchemy ORM
  • Deployment: Render-compatible (modular provider architecture)

Core Prompt Engineering Techniques Explained

Key theoretical concepts implemented in this project for academic evaluation:

1. Role Prompting

Assigns a specific persona (e.g., "Executive communication specialist" or "Distinguished computer science educator"). Primes the LLM's latent weights toward relevant vocabulary and professional demeanor.

2. Instruction Prompting

Directs the LLM with unambiguous, imperative steps (e.g., "Structure with a subject line, clear body, and sign-off") to ensure actionable and direct execution.

3. Context Prompting

Supplies background situational details or past conversational turns (used in Regenerate, Improve, Shorten, Expand) so the model makes contextually informed revisions.

4. Audience Conditioning

Adapts linguistic complexity and technical depth based on whether the reader is a Beginner (analogies, plain terms) or Technical Expert (algorithmic details, trade-offs).

5. Tone Control

Guides sentiment and stylistic register across Professional, Friendly, Academic, Simple, and Formal tones.

6. Length & Boundary Enforcement

Specifies structural boundaries (Short, Medium, Detailed) to prevent verbose rambling or insufficient shallow output.

7. Output Formatting Constraints

Enforces explicit Markdown scaffolding (e.g., `# Executive Summary`, `## Findings`), guaranteeing predictable structural layout.

8. Few-Shot Concept & Hallucination Prevention

Includes strict negative constraints (e.g. "Do not invent real names or personal data. Use placeholders like [Your Name]") to prevent hallucinated personal identities.

Drawbacks of Naive Prompt:
  • No defined target audience (may be too complex or too basic)
  • No structural boundaries (unpredictable length and layout)
  • No tone guidance (inconsistent style)
  • High risk of irrelevant or rambling explanations
